# 保护性关切记录与安全接管后端（Safeguarding Concern Handoff）

NestJS + SQLite 实现。供学校教职员记录学生保护性关切（例如学生表示「不愿回家」但未说明原因），
由风险规则确定**接管时限与可见角色**，驱动接管确认、超时升级、最小必要披露与外部专业人员移交。

设计底线：**系统只记录事实陈述与操作状态，绝不自动对学生或家庭成员下结论。**
所有事实初始为「未核实」，核实只能由保护人员人工登记。

## 运行

```bash
npm install
npm run build
npm start                 # 默认 127.0.0.1:3000
# 可选环境变量：PORT、HOST、SAFEGUARD_DB_PATH
npm test                  # 16 个 e2e 场景测试
```

身份认证用请求头 `x-staff-id` 模拟（生产应替换为学校 SSO/JWT，访问控制模型不变）。
预置账号：

| id | 角色 |
|---|---|
| `dsl-001` | 保护负责人（safeguarding_lead） |
| `dsl-002` | 副保护负责人 |
| `head-001` | 校长 |
| `t-001` / `t-002` / `t-003` | 课后活动老师（c-1 / c-2 / c-3 班） |

SQLite 使用 Node 22 内置 `node:sqlite`（无原生编译依赖）。

## 核心规则

- **风险规则只决定操作参数，不认定事实**（`src/domain/risk-policy.ts`）
  - 即时危险信号 / 现场判断即时危险 → 紧急，30 分钟内接管，副保护负责人同步可见备援
  - 述称伤害 / 不明伤痕 / 害怕家中某人 → 急件，4 小时内接管
  - 其余（含仅「不愿回家」原因不明）→ 常规，24 小时内接管
- **匿名咨询**：身份未识别，仅保护负责人可见，7 日内阅看，不启动接管时钟与升级链；禁止携带学生标识。
- **超时逐级升级**：保护负责人 → 副保护负责人 → 校长；每级授权、新时限、旧动作状态全部留痕；
  到顶仍未接管则留终局告警，不再自动外发。扫描幂等，每 60 秒执行一次（可手动调 `tickEscalations`）。
- **最小必要知情（need-to-know）**，四类视图：
  - `investigation`：风险规则/升级授权的保护人员，见完整调查细节与责任视图
  - `reporter`：记录者本人，只见自己提交的事实、核实状态、自己必须执行的动作
  - `action`：被指派最小必要动作的普通老师，只见动作与执行上下文，不见原话与调查细节
  - `disclosure`：经单次披露授权者，仅见当次披露字段
- **连续时间线**：补充信息、接管、升级、披露、核实、合并拆分等全部进入同一时间线并连续编号。
- **合并 / 拆分**：仅保护负责人可合并相关线索（授权取并集、事实保留 `origin_concern_id` 来源）；
  误合并拆分后，原合并理由与拆分理由（依据）永久保留。
- **撤回联系方式**：抹除联系方式本体、保留「已撤回」墓碑；之后任何外部移交携带该联系方式都会被拒绝。
- **外部移交**：须先接管；必须填写移交内容（scope）与责任划分（responsibility），可登记接受/拒绝回执。
- **责任视图**：谁正在接管、何时到期、是否超时、哪些事实尚未核实、每次披露的对象/理由/字段、
  合并拆分依据，全部可在 `GET /concerns/:id` 按视图级别获取。

## API

| 方法与路径 | 说明 |
|---|---|
| `POST /concerns` | 初次记录：原话、发生时间、现场安全、已采取最小措施、风险信号 |
| `GET /concerns` | 我的关切工作台（按访问范围投影） |
| `GET /concerns/:id` | 责任视图（按视图级别返回不同内容） |
| `POST /concerns/:id/supplements` | 补充信息（进入连续时间线，可附 `contactRetraction`） |
| `POST /concerns/:id/takeover-ack` | 接管人确认已收到（实名报告） |
| `POST /concerns/:id/review-ack` | 匿名咨询阅看确认 |
| `POST /concerns/:id/follow-ups` | 指派最小必要动作（可跨班） |
| `POST /concerns/actions/:actionId/ack` | 被指派人确认收到 / 完成 |
| `POST /concerns/:id/referrals` | 移交外部专业人员（内容 + 责任） |
| `POST /concerns/referrals/:id/respond` | 登记外部接受/拒绝回执 |
| `POST /concerns/:id/disclosures` | 最小必要披露（对象 + 理由 + 字段） |
| `POST /concerns/:id/merges` / `/unmerges` | 合并线索 / 误合并拆分（保留依据） |
| `POST /concerns/:id/verifications` | 人工登记事实核实（verified / refuted） |
| `POST /concerns/:id/close` | 关闭并记录摘要 |

## 自动化场景覆盖（`test/`，16 个用例）

- 重复报告：同一学生两条线索合并为连续时间线，误合并后拆分并保留双向依据
- 跨班转交：跨班老师收到最小必要动作，不接触原话与调查细节，且只能确认自己的动作
- 撤回联系方式：抹除 + 墓碑，撤回后移交禁止再携带，且只能本人撤回
- 超时升级：逐级授权与时限、幂等扫描、到顶终局告警、接管后升级链终止
- 匿名咨询与实名报告的访问范围隔离
